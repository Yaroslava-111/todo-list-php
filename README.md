# Список задач — PHP + MySQL / SQLite

Личный список задач с хранением на сервере. Один владелец, один пароль, задачи доступны с любых устройств после входа.

- **Два движка на выбор:** SQLite (по умолчанию, ничего устанавливать не нужно) или MySQL 8.0+ / MariaDB. Интерфейс одинаков.
- **Серверное хранение:** задачи живут в базе, а не в браузере; ошибка связи не теряет данные.
- **Без зависимостей:** PHP 8.2+ с PDO, Composer и Node.js не нужны.
- **Безопасность по умолчанию:** пароль хранится только как хеш, CSRF-токены, лимит попыток входа (10 за 15 минут), HttpOnly-сессии, строгая валидация всех данных на сервере, XSS-безопасный рендер.

## Структура проекта

| Каталог | Содержимое |
|---|---|
| `public/` | Document root сайта: страница, стили, JS и `api.php` |
| `private/` | Конфиг, приложение (`app.php`); здесь же живут SQLite-файл и сессии. **Держите вне document root** |
| `sql/` | Схемы баз: `sqlite.sql` и `mysql.sql` |
| `tools/` | CLI-скрипты установки: `install.php` и `password.php` |

## Требования

- PHP 8.2+ с расширениями: `pdo_sqlite` **или** `pdo_mysql` (плюс `pdo`, `session`, JSON, PCRE Unicode).
- Для SQLite: PHP должен иметь право записи в каталог `private/`.
- Для MySQL: база в `utf8mb4`, таблицы InnoDB.
- HTTPS на продакшене.

## Быстрый старт (локально)

```bash
# 1. Скопируйте конфиг
cp private/config.example.php private/config.php

# 2. Задайте в config.php:
#    'driver'        => 'sqlite',
#    'app_url'       => 'http://localhost:8000',
#    'require_https' => false,

# 3. Сгенерируйте хеш пароля (12–128 символов) и вставьте его в 'password_hash'
php tools/password.php

# 4. Создайте схему базы
php tools/install.php

# 5. Запустите сервер
php -S 127.0.0.1:8000 -t public
```

Откройте `http://localhost:8000` и войдите с паролем, хеш которого вы задали.

## Установка на хостинг

1. Разместите содержимое `public/` в document root (например, `public_html/`), а каталоги `private/`, `tools/`, `sql/` — **рядом с ним, не внутри**. Относительный путь API к `private/` уже настроен на такую структуру.
2. Скопируйте `private/config.example.php` → `private/config.php`. Укажите точный origin сайта в `app_url` (например, `https://tasks.example.com`, без завершающего слэша и пути).
3. Сгенерируйте хеш пароля (`php tools/password.php`) и вставьте его в `password_hash`. Открытый пароль в конфиг не записывается. Для MySQL заполните секцию `mysql` (база и пользователь создаются заранее; root не использовать).
4. Выполните `php tools/install.php` — скрипт создаёт таблицы и каталог сессий. Повторный запуск поверх существующих таблиц безопасно прерывается.
5. Права доступа: `config.php` и SQLite-файл — `0600`, каталоги `private/` и `sessions/` — `0700`. Не используйте `0777`.
6. Откройте сайт по HTTPS и войдите.

## Безопасность

- Пароль хранится исключительно в виде хеша (`password_hash` от SHA-256-дайджеста); открытый пароль нигде не сохраняется.
- `config.php` и база находятся вне document root и не публикуются. `.htaccess` в архиве — дополнительная защита для Apache.
- Все проверки данных выполняются на сервере: названия задач (1–200 символов после нормализации пробелов), лимит 500 задач, типы JSON, конфликт версий списка (`409` при устаревшей ревизии).
- Вход ограничен 10 попытками на IP за 15 минут; сессия истекает после 8 часов неактивности.
- Ответы API не содержат паролей и деталей подключения к базе.

## Диагностика

- `503` от API — проверьте `config.php`, PDO-драйвер, установку схемы (`php tools/install.php`) и права каталогов.
- `400` с текстом про HTTPS — откройте сайт по HTTPS или отключите `require_https` только для локальной разработки.
